# engineering-constraints Specification

## Purpose

Среды, источники зависимостей, ограничения проверок и критерии технической приёмки приложения.

## Requirements

### Requirement: ENG-001 Среды и зависимости

Приложение SHALL использовать отдельные среды и источники зависимостей, указанные в таблице.

| Среда                        | Основа и источник конфигурации                                                                         |
|------------------------------|--------------------------------------------------------------------------------------------------------|
| Основная                     | Python 3.14 x64, .venv; [requirements.txt](../../../requirements.txt)                                  |
| Parakeet                     | Python 3.14, resources/runtimes/parakeet; [parakeet.txt](../../../requirements-workers/parakeet.txt)   |
| Qwen ASR/aligner             | Python 3.11, resources/runtimes/qwen; [qwen.txt](../../../requirements-workers/qwen.txt)               |
| Установка изолированных сред | [setup_workers.ps1](../../../setup_workers.ps1)                                                        |
| Браузер                      | [package.json](../../../package.json), package-lock.json, Playwright                                   |

Точные версии зависимостей задаются соответствующим requirements; основной граф SHALL NOT изменяться ради
несовместимой изолированной среды. Подготовка сред описана в
[командах установки](../../../README.md#подготовка-сред).

#### Scenario: Подготовка Qwen

- **WHEN** подготавливается среда Qwen ASR или aligner
- **THEN** используется Python 3.11 и requirements-workers/qwen.txt отдельно от основного Python 3.14 x64

### Requirement: ENG-002 Установка пакета и сборочные артефакты

Установка приложения SHALL выполняться через pip с отдельной установкой зависимостей по requirements.txt.
Конфигурация пакета — [pyproject.toml](../../../pyproject.toml), версия берётся из
[__init__.py](../../../speech_to_sub/__init__.py).
pyproject dependencies=[] и Requires-Dist=0 — известное ограничение: wheel не устанавливает зависимости приложения.
Внешний пакетный реестр требует отдельного контракта.
[Workflow сборки](../../../.github/workflows/python-release-build.yml) после публикации GitHub Release SHALL
собирать дистрибутивы и сохранять их как артефакты GitHub Actions.

#### Scenario: Установка wheel

- **WHEN** приложение устанавливается из wheel
- **THEN** зависимости приложения устанавливаются отдельно по requirements.txt; наличие wheel не подтверждает их установку

### Requirement: ENG-003 Границы проверок

Обычные тесты SHALL использовать имитации и временные данные без реальных весов, пользовательских оригиналов и платных
вызовов. Тяжёлые интеграционные проверки SHALL включаться явно; отказные проверки и результаты размещаются в тестовом
каталоге. Условия сети и облака определены в
[ASR-002](../speech-recognition/spec.md#requirement-asr-002-локальная-готовность),
[ASR-003](../speech-recognition/spec.md#requirement-asr-003-разрешённая-докачка) и
[ASR-008](../speech-recognition/spec.md#requirement-asr-008-явный-облачный-режим).
Команды и параметры включения — в [процедуре проверок](../../../README.md#проверки).

#### Scenario: Обычный запуск тестов

- **WHEN** тесты запущены без явного включения тяжёлой интеграционной проверки
- **THEN** используются имитации и временные данные без реальных весов, пользовательских оригиналов и платных вызовов

### Requirement: ENG-004 Анализ Sonar и граница покрытия

Ключ проекта — speech-to-sub-recognition; [пример конфигурации](../../../sonar-project.properties.example).
Адрес задаётся через SONAR_HOST_URL, токен — через SONAR_TOKEN в локальном окружении.
Нужны проектная среда, sonar-scanner, Node.js и доступный сервер.

Для приёмки нового дерева SHALL выполняться свежий анализ с завершённой вычислительной задачей (CE), чистым шлюзом
качества, отсутствием открытых замечаний и замечаний SECURITY, проверкой дублирования и порога покрытия.
-SkipScanner проверяет прежний анализ. Команда и полная процедура — в
[процедуре Sonar](../../../README.md#sonar).

Клиентская статика входит в анализ; без LCOV её нет в численном покрытии. Playwright проверяется отдельно.
Включение браузерного покрытия SHALL требовать сбора LCOV, sonar.javascript.lcov.reportPaths и новой проверки
объединённой метрики.

#### Scenario: Проверка прежнего анализа

- **WHEN** проверка запущена с -SkipScanner
- **THEN** её результат относится к прежнему анализу и не подтверждает приёмку нового дерева

#### Scenario: Клиентская статика без LCOV

- **WHEN** LCOV для клиентской статики отсутствует
- **THEN** статика участвует в анализе, но не включается в численное покрытие; Playwright проверяется отдельно
