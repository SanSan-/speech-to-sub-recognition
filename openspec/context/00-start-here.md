# Начало работы
1. Обязательно прочитай [продукт](01-product-context.md), [инженерную спецификацию](../specs/engineering-governance/spec.md), её [общие правила](../specs/engineering-governance/reference/python-common.md) и [проектные правила](../specs/engineering-governance/reference/project-specific.md).
2. Сверь [безопасность](05-security-and-compliance.md) и [антипаттерны](07-anti-patterns.md).
3. Выбери [термины](02-domain-glossary.md), [архитектуру](03-architecture.md), [команды](04-engineering-standards.md), [качество](06-testing-and-quality.md), [примеры](examples/README.md) и [решения](ADR/README.md) по задаче.
4. Найди продолжение в [открытых изменениях](../changes/README.md); предметные спецификации перечислены в архитектуре.
5. Не меняй исходные медиа и результаты без предусмотренного разрешения; не выдавай старое доказательство за новую проверку.
6. Противоречие описания с кодом обрабатывай по [CTX-002](../specs/project-context/spec.md); ошибки контекста фиксируй в [журнале](failure-log.md).

Автоматически во время работы: [контекст, сводки и окно — CTX-005…008](../specs/project-context/spec.md); [безопасность контекста — SEC-CONTEXT-001…004](../specs/engineering-governance/spec.md).

Методика аудита CTX-009 применяется только по отдельному явному запросу.
