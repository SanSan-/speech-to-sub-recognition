# Журнал изменений

## Релиз 1.9.0 - 2026-10-16

- Очистка устаревших рабочих каталогов исключает Windows junction до разрешения пути к цели.
  Цель больше не удаляется через такую ссылку, в том числе внутри `WORK_DIR` при старом маркере
  владения и отсутствии активной блокировки.
- [WEB-010](openspec/specs/local-web-workflow/spec.md#requirement-web-010-очистка-и-история) закрепляет
  сохранность junction и его цели и продолжение очистки обычного устаревшего каталога рядом с ним.

## Релиз 1.8.0 - 2026-10-15

- Python выбранного изолированного движка Qwen/Parakeet и выравнивателя Qwen проверяется до проверки
  потоков медиа, нормализации и обращения к кешу. Отсутствующий файл или каталог вместо интерпретатора
  отклоняет весь запуск, включая force, без изменения существующих результатов.
- [IFACE-001](openspec/specs/application-interface/spec.md#requirement-iface-001-разрешение-и-проверка-настроек)
  закрепляет раннюю проверку без запуска Python, загрузки весов и сетевых запросов. Недоступные пути
  невыбранных профилей не препятствуют обработке; приоритеты явных настроек и окружения сохранены.

## Релиз 1.7.0 - 2026-10-15

- Исправлено облачное согласие CLI: каждый запуск требует собственного `--allow-cloud-processing`;
  переменная окружения и `.env` не разрешают следующий запуск без флага.
- Чтение JSON-кеша ограничено 64 МиБ до декодирования UTF-8 и разбора JSON. Превышение предела исключает
  повторное использование файла без его изменения, удаления или усечения.
- При отказе кеша по размеру сохраняются все существующие результаты выбранного формата, включая неполный
  набор без субтитров. Полностью отсутствующий формат создаётся из следующего пригодного кеша либо новым
  распознаванием; соседние результаты сохраняются.
- Повторный отказ чтения кеша перед добавлением FLAC завершает обработку файла контролируемой ошибкой до
  публикации; остальные файлы пакета продолжают работу.
- При тайм-ауте ffprobe в Windows завершается всё принадлежащее запуску дерево процессов, включая потомков
  уже завершившегося родителя. Открытые каналы вывода больше не задерживают возврат ошибки.
- [ART-005/006/010](openspec/specs/recognition-artifacts/spec.md) различают превышение предела и обычный
  повреждённый кеш, закрепляют байтовую границу и сохранность результатов; явный force сохраняет полный пересчёт.

## Релиз 1.6.0 - 2026-08-11

### Добавлено

- В основных настройках командного и веб-интерфейсов доступен выбор формата субтитров: SRT,
  ASS или WebVTT. Значение по умолчанию остаётся SRT, а несекретный выбор веб-интерфейса
  сохраняется в `localStorage`.
- Общая раскладка распознанного текста публикуется через профильные формирователи и валидаторы
  SRT, ASS и WebVTT. Все текстовые результаты записываются в UTF-8 без BOM и заменяются
  атомарно.
- Формирователь событий ASS перенесён из `sub-translator-py`: первые девять полей
  `Dialogue` сохраняются, заменяется только `Text`, а адаптер ASR формирует канонический
  документ и защищает буквальный текст от управляющих последовательностей ASS.
- Команда `speech-to-sub --version` выводит текущую версию приложения без запуска обработки.

### Изменено

- Поля результата API обобщены для выбранного формата; прежнее поле `srt_output` содержит путь
  только для совместимых результатов SRT и равно `null` для ASS и WebVTT.
- Прежние имена SRT, его сопроводительного JSON и необязательного FLAC сохранены. ASS и WebVTT
  получают отдельные форматные имена субтитров, JSON и FLAC, поэтому смена формата не затрагивает
  результат другого формата.
- Тяжёлый отпечаток распознавания не зависит от выходного формата: совместимый сохранённый
  `Transcript` используется для формирования другого формата без повторного запуска модели.

### Исправлено

- При одновременном сбое публикации и отката невосстановленная резервная копия прежнего
  пользовательского артефакта сохраняется для безопасного восстановления и не удаляется
  очисткой транзакции.

## Релиз 1.5.3 - 2026-08-11

### Добавлено

- GitHub Actions при публикации GitHub Release собирает `sdist` и wheel на Python 3.14 и
  сохраняет их единым артефактом `release-dists`.
- Состояние подготовки `GET /api/preparation-status` с ограниченным русским журналом, фазами
  выбора, обхода, проверки потоков и постановки задачи, неубывающими счётчиками, корреляцией по
  поколению и `operation_id` и терминальной ошибкой.
- Отдельный журнал веб-сессии `logs/speech_to_sub-web.log` в UTF-8 без BOM: запуск
  приложения, задачи, доступ и ошибки Uvicorn пишутся через единственный ротационный обработчик
  Python в один файл с пределом 5 МиБ и тремя архивами.
- Видимые сообщения о потере сервера, необработанных ошибках JavaScript и отклонённых
  асинхронных операциях в журнале браузера.
- Постраничный список по 200 карточек для пакетов до 10 000 файлов с индексом элементов по пути
  и инкрементальной сводкой.

### Изменено

- Кнопка «Папка» всегда рекурсивно собирает поддерживаемые медиа из всех вложенных каталогов;
  обновление и постановка задачи сохраняют этот контракт независимо от прежних настроек
  браузера. Символические ссылки и соединения каталогов Windows (`junction`), обнаруженные
  внутри выбранного каталога, а также служебные `*.asr.flac` исключаются из обхода.
  Для командной строки рекурсивность по-прежнему включается через `--recursive`.
- Подготовка карточек больше не вычисляет полный SHA-256 исходников. До четырёх процессов
  `ffprobe` работают параллельно, а порядок карточек остаётся детерминированным.
- Изменение настройки больше не запускает скрытую повторную проверку всех выбранных файлов;
  актуализация выполняется явным обновлением, новым выбором или при постановке задачи.

### Исправлено

- Длительный выбор большого дерева каталогов теперь сразу показывает ход работы вместо пустого
  журнала. Пустой, исчезнувший или недоступный для получения атрибутов файл остаётся отдельной
  ошибкой без фиктивных выходных путей, а исправные соседи продолжают подготовку и обработку.
- Текущий запуск веб-интерфейса и ошибки сервера больше не остаются только в консоли Uvicorn.
- Большой пакет больше не создаёт одновременно тысячи узлов страницы и не выполняет линейный
  поиск по всем файлам для каждого события.
- Конфликтный запуск с ответом `409` больше не меняет состояние действующей подготовки, а
  рабочие изменяющие запросы без точного локального `Origin` отклоняются.
- Тайм-аут `ffprobe` в 30 секунд на Windows завершает всё дочернее дерево процесса; ошибка
  остаётся у одного файла и не останавливает пакет.
- OpenAPI явно описывает ответ HTTP 500 для обновления карточек и запуска распознавания.
- Внутренний обход путей и клиентское наблюдение за подготовкой разделены на небольшие функции,
  а браузерные тесты синхронизируются по наблюдаемому состоянию без фиксированных задержек.
- Длинная сводка смешанных состояний большого пакета переносится внутри шапки файлов и больше не
  обрезается на промежуточных и узких ширинах окна.
- Стадии обработки больше не дублируются в файловом веб-журнале: сервис пишет одну строку, а
  обратный вызов задачи передаёт ту же стадию только в поток событий браузера.
- Длительность медиа снова видна у обрабатываемой и завершённой карточки сразу после успешного
  рабочего `ffprobe`, сохраняется при ошибке или отмене после проверки и после перезагрузки
  страницы; неизвестное значение больше не показывается как `0:00`.

## Релиз 1.5.2 - 2026-08-10

### Изменено

- Компоновка SRT теперь сначала глобально распределяет готовый текст по смысловым строкам и
  соседним репликам, а затем отдельно назначает время по словным якорям.
- Значения 17 символов в секунду, 0,8–7,0 секунды и целевая ширина строки стали ориентирами
  раскладки и диагностики, а не условиями публикации результата.
- Версия сборщика SRT повышена: прежний кеш строгой раскладки не считается готовым результатом
  для нового контракта.

### Исправлено

- Быстрая речь, длинные паузы внутри незаконченной фразы, растянутые метки и неделимый длинный
  токен больше не приводят к ошибке компоновки непустого результата распознавания.
- Балансировка устраняет однословные начала и хвосты, объединяет продолжение через технические
  границы сегментов; пауза не разрывает незавершённое предложение.
- Сопроводительный JSON сохраняет число превышений ориентиров и фактические максимумы скорости
  чтения, длительности реплики и длины строки.

## Релиз 1.5.1 - 2026-08-10

### Изменено

- Флаг перезаписи стал одноразовым: он не сохраняется в браузере, сбрасывается после отправки
  задачи и требует нового явного включения для повтора.

### Исправлено

- Флаг перезаписи теперь обходит как готовый SRT-кеш, так и сохранённый результат распознавания:
  движок и выбранное выравнивание запускаются заново, а карточка предварительной проверки больше
  не показывает кеш как готовый к переиспользованию.
- Веб-API и сервис принимают для флага перезаписи только логические `true` или `false`; строки и
  числа отклоняются до начала обработки.

## Релиз 1.5.0 - 2026-08-09

### Добавлено

- Автоматическая докачка отсутствующих или неполных локальных моделей из закреплённых
  репозиториев Hugging Face непосредственно в `ASR_MODEL_PATH` или
  `ASR_ALIGNER_MODEL_PATH`.
- Локальная проверка обязательных файлов модели, предварительная оценка свободного места,
  межпроцессная блокировка, продолжение незавершённой загрузки и атомарный маркер готовности.
- Настройка `ASR_AUTO_DOWNLOAD_MODEL` и параметр `--no-auto-download-model` для явного запрета
  сетевой докачки.
- Необязательный движок `openai-api` только для `whisper-1` со словными и сегментными временными
  метками, подготовкой ограниченных по размеру частей и удалением дублей перекрытия.
- Отдельное согласие на облачную обработку через `ASR_ALLOW_CLOUD_PROCESSING`,
  `--allow-cloud-processing` и веб-интерфейс.
- Переменные `OPENAI_TRANSCRIPTION_MODEL`, `OPENAI_API_KEY` и `HF_TOKEN`; секретные значения
  остаются только в локальном окружении.
- Макетные проверки клиента OpenAI, скачивания моделей, облачного контрольного отпечатка и
  повторного запроса согласия в браузере.

### Изменено

- Локальный режим сохранён основным, а сеть используется для модели только после реального
  промаха кеша; полная модель, проверка работоспособности и совпавший кеш работают без обращения
  к Hugging Face Hub.
- Для облачного результата контрольный отпечаток учитывает поставщика и `whisper-1`, но не ключ,
  согласие, локальный путь модели, устройство или квантование.
- Рабочая область веб-интерфейса растягивается по доступной высоте настольного окна; список файлов
  и настройки прокручиваются независимо, а узкий экран сохраняет естественный вертикальный поток.
- В основное окружение добавлен закреплённый клиент OpenAI и его прямые зависимости.

### Исправлено

- Согласие на облачную обработку больше не сохраняется в `localStorage` и требуется перед каждой
  новой задачей.
- Подпись среды облачного движка использует `device=cloud`, а не локальное устройство.
- Пользовательские облачные ошибки не сохраняют исходное сообщение поставщика в цепочке
  исключений и не раскрывают его через полную трассировку.
- Запись о завершении докачки модели выполняется только в достижимой ветке события готовности.
- Имена обязательных файлов моделей сведены к константам, а проверка индексированных шардов
  разделена на небольшие функции без изменения правил безопасности пути.
- Проверки исключений готовят входные данные до целевого вызова и однозначно фиксируют источник
  ожидаемой ошибки.

## Релиз 1.4.2 - 2026-08-09

### Добавлено

- Глобальная разметка SRT по границам предложений через технические границы сегментов
  распознавания.
- Настраиваемые базовая длина строки, адаптивный допуск и жёсткий предел скорости чтения в
  командном и веб-интерфейсах, `.env.example`, проверке результата и лёгком отпечатке
  `layout_settings`.
- Регрессионные сценарии для пунктуации, русского тире, внутрисловного дефиса, суффикса `-то`
  и начальной аномальной временной метки.
- Ограниченное смещение внутренней границы реплик для физически плотной речи и диагностические
  показатели числа и максимальной величины таких сдвигов.
- Диагностическое поле `timing_anomaly_adjustments` для числа узких нормализаций растянутых
  словных якорей.
- Схема сопроводительного JSON версии 2 с отдельными `recognition_settings` и
  `layout_settings`, а также строгим восстановлением сохранённого `Transcript`.

### Изменено

- `segment.text` используется как источник текста, регистра и пунктуации; словные метки служат
  временными якорями.
- Разметка выполняется в порядке «словные якоря → предложения → смысловые строки → отдельное
  назначение времени»; временное планирование больше не определяет смысловой перенос строк.
- Новое предложение начинается с новой строки либо новой реплики.
- Разметка предпочитает строки до 42 символов, но ради цельной фразы или устранения неудачного
  короткого остатка допускает до 8 дополнительных символов; жёсткий предел по умолчанию равен
  50 символам, а значение допуска `0` сохраняет прежнее строгое поведение.
- Остальные жёсткие пределы составляют две строки, 17 символов в секунду и 0,8–7,0 секунды.
- Тяжёлый кеш распознавания и выравнивания отделён от лёгкой SRT-разметки: изменение только
  версии сборщика, базовой длины, адаптивного допуска или CPS пересобирает SRT без модели.
- Отсутствующий SRT восстанавливается из совпавшего `Transcript` без `force`; существующий SRT
  с другой раскладкой по-прежнему заменяется только при `force=true`.
- Сопроводительный JSON прежней схемы для конвейера 7 и сборщика 2 допускается только как
  источник тяжёлого кеша; другие версии конвейера не переиспользуются.
- Внутренняя граница может отклоняться от неточной словной метки не более чем на 1,0 секунды
  только внутри непрерывного речевого блока; начало, конец и паузы от 0,8 секунды не
  пересекаются.
- `.env.example` и шаблон SonarQube очищены от значений конкретной машины.
- Пути моделей по умолчанию перенесены в `resources/models`; локальные каталоги задаются
  переменными окружения и больше не зашиты в исходный код.

### Исправлено

- Пунктуация больше не должна теряться после словного выравнивания.
- Неполный результат Qwen3 ForcedAligner не заменяет полный проверенный набор исходных словных
  меток `faster-whisper`; причина возврата сохраняется в метаданных.
- Изменение только параметров SRT больше не запускает повторно FFmpeg, движок распознавания и
  модуль выравнивания, если сохранение нормализованного аудио не требуется.
- Аномально растянутые словные якоря узко нормализуются до формирования предложений, не меняя
  текст, порядок слов и исходный `Transcript`.
- Подсказка режима перезаписи теперь явно сообщает о возможном переиспользовании совместимого
  кеша распознавания.
- Диагностика разметки всегда содержит счётчик временных аномалий и учитывает оба направления
  сдвига внутренних границ без двойного подсчёта общей границы.

## Релиз 1.4.0 - 2026-08-09

### Добавлено

- Общий слой обработки для командного и веб-интерфейсов.
- `ffprobe`, FFmpeg, локальный Whisper, выбор CUDA или процессора, SRT и диагностический
  сопроводительный JSON.
- Кеш, `force`, защита коллизий, атомарная запись и межпроцессная блокировка.
- Пакетный FastAPI/SSE-интерфейс и реальные проверки русских и английских MKV и MP4.
- Время начала и окончания обработки в сопроводительном JSON.
- Проверки контейнера с несколькими дорожками, пакета с повреждённым файлом, повторного прохода
  по кешу и восстановления страницы.
- Реестр движков и основной профиль `faster-whisper` с CTranslate2.
- Оконная обработка длинных записей через PyAV без единого массива несжатого аудио всего файла.
- SQLite-хранилище, восстановление после перезапуска, отмена, повтор только неуспешных файлов,
  продолжение SSE по курсору и ограниченная очистка.
- Локальные движки Parakeet TDT v3 и Qwen3-ASR 0.6B в изолированных процессах.
- Самостоятельный Qwen3 ForcedAligner через общий контракт выравнивания.
- Выбор движка и выравнивания без привязки клиентской части к конкретной реализации.
- Инструмент запуска выбранного локального движка с измерением времени обработки и сохранением результата в JSON.

### Изменено

- `faster-whisper` выбран основным профилем длинных записей по собственным измерениям;
  `transformers` сохранён как запасной профиль совместимости.
- Qwen3-ASR и Qwen3 ForcedAligner загружаются в отдельных последовательных процессах.
- Длинные сегменты выравнивания ограничены 180 секундами.
- Контрольный отпечаток кеша раздельно учитывает движок, модель, среду выполнения и
  выравнивание.
