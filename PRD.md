# PRD: speech-to-sub-recognition

## Назначение

`speech-to-sub-recognition` — локальное Windows-first приложение для пакетного преобразования
видеофайлов и аудиозаписей в субтитры SRT. Приложение инвентаризирует аудиопотоки через
`ffprobe`, извлекает и нормализует выбранную дорожку через FFmpeg, выполняет распознавание
локальной ASR-моделью и формирует проверенный `.srt` в UTF-8 без BOM.

V1 начиналась с локального Hugging Face checkpoint `whisper-large-v3`. В V1.2 основным
long-form runtime стал локально сконвертированный `whisper-large-v3-ct2`; исходный checkpoint
остаётся fallback. V1.3 добавила устойчивую SQLite-очередь, recovery, cancel и retry. В V1.4
единый контракт расширен локальными Parakeet TDT v3, Qwen3-ASR 0.6B и optional Qwen3
ForcedAligner. Английский и русский проверены на локальном CUDA runtime.

## Источники и принятые решения

Приоритет требований:

1. Прямые указания пользователя и локальный `AGENTS.md`.
2. Свежие правила, зафиксированные зависимости и структура PRD из `ocr-local`.
3. Реализованный desktop-web batch UI, фоновые задания и SSE из `sub-translator-py`.
4. Исследовательские документы из `docs` о FFmpeg, локальных ASR-моделях и SRT.

Исследования расходятся в выборе одной «лучшей» модели: предлагаются Parakeet,
faster-whisper и разные Whisper checkpoint-ы. V1 была построена на доступном пути:

```text
D:\Projects\-ai\+automatic-speech-recognition\whisper-large-v3
```

Он совместим со стеком PyTorch/Transformers из `ocr-local` и позволил проверить полный
offline-пайплайн. В V1.2 тот же checkpoint сконвертирован в CTranslate2, реализован реестр
backend-ов и оконный faster-whisper. Выбор основного runtime подтверждён собственным
long-form benchmark. В V1.4 Parakeet/Qwen/aligner-ы реализованы через общие registry и
изолированные worker-процессы, поэтому несовместимые ML-зависимости не попадают в основной venv.

## Цель первой версии

Сделать минимальный, проверяемый сквозной пайплайн:

1. Выбрать один или несколько локальных файлов либо папку.
2. Проверить наличие FFmpeg, ffprobe и локальной модели.
3. Получить метаданные аудиопотоков и выбрать дорожку по настройкам.
4. Создать временную ASR-копию: mono, 16 kHz, FLAC.
5. Распознать речь локальной моделью и получить сегменты с временными метками.
6. Сформировать читаемые, непересекающиеся SRT-реплики.
7. Проверить и атомарно записать `.srt` и sidecar JSON.
8. Показать состояние каждого файла и поток логов в локальном веб-интерфейсе.
9. Повторный запуск не должен заново обрабатывать неизменённый готовый результат без
   явно включённого `force`.

## Основные пользовательские сценарии

### Папка с лекциями

Пользователь запускает веб-интерфейс, выбирает папку с MP4, задаёт язык `en`, локальную
модель и запускает обработку. UI показывает стадии и прогресс каждого файла. Ошибка одного
файла не останавливает остальные.

### Несколько выбранных файлов

Пользователь выбирает несколько видео- и аудиофайлов через системный диалог. Для каждого
файла UI показывает вход, выбранный аудиопоток, путь SRT, статус и ошибку, если она возникла.

### MP4 с несколькими дорожками

До запуска распознавания приложение показывает индекс, язык, title, кодек, число каналов и
частоту дискретизации аудиопотоков. Пользователь может указать индекс дорожки. Автоматическая
политика сначала ищет уникальный язык `eng`; неоднозначность отражается предупреждением и не
скрывается от пользователя.

### Повторный запуск

Если источник и значимые настройки совпадают с валидным sidecar и SRT, файл получает статус
`cached`. Если существующий SRT не подтверждён sidecar, он не перезаписывается и получает
статус `skipped`, пока пользователь явно не включит `force`.

## Требования к CLI

Запуск одного файла:

```powershell
python -m speech_to_sub --input "lecture.mp4"
```

Запуск папки:

```powershell
python -m speech_to_sub --input "D:\Media\Lectures" --recursive
```

Параметры первой версии:

- `--input` — входной файл или папка.
- `--output-dir` — необязательный корень результатов; без него SRT создаётся рядом с исходником.
- `--recursive` — рекурсивный обход выбранной папки.
- `--language` — `en`, `ru` или `auto`; по умолчанию `en`.
- `--audio-stream-index` — нулевой порядковый номер аудиопотока; имеет приоритет над языком.
- `--audio-language` — код языка дорожки, по умолчанию `eng`.
- `--backend` — `faster-whisper`, `transformers`, `parakeet-tdt-v3` или `qwen3-asr`;
  по умолчанию faster-whisper.
- `--model-path` — путь к локальной ASR-модели выбранного формата.
- `--aligner` — `none` или `qwen3-forced-aligner`; Qwen aligner принимает общий transcript
  любого backend-а с определённым языком и сам делит длинные сегменты на части до 180 секунд.
- `--aligner-model-path` — локальный checkpoint optional aligner-а.
- `--worker-python-path` — явный Python изолированного ASR backend runtime.
- `--aligner-worker-python-path` — независимый Python изолированного aligner runtime.
- `--device` — `auto`, `cuda` или `cpu`; по умолчанию `auto`.
- `--no-quantization` — отключить 8-битную загрузку, не отключая CUDA.
- `--allow-cpu-fallback` — разрешить повторную загрузку модели на CPU после ошибки CUDA.
- `--long-form-window-seconds` и `--long-form-overlap-seconds` — безопасные окна CTranslate2.
- `--no-vad`, `--vad-min-silence-ms`, `--beam-size` и
  `--no-condition-on-previous-text` — управляемые параметры long-form распознавания.
- `--keep-audio` — сохранить нормализованный FLAC рядом с результатом.
- `--force` — игнорировать кеш и атомарно заменить только целевые артефакты.
- `--verbose` — подробный журнал.

Коды завершения:

- `0` — все файлы готовы, взяты из кеша или безопасно пропущены;
- `1` — ошибка конфигурации или входных данных до запуска пачки;
- `2` — пачка завершена, но один или несколько файлов имеют статус `error`.

## Требования к веб-интерфейсу

Запуск:

```powershell
.\run_web.ps1
```

По умолчанию приложение доступно только на `http://127.0.0.1:7862`.

Из `sub-translator-py` переносится и адаптируется desktop-web сценарий:

- FastAPI раздаёт статические HTML/CSS/JS;
- кнопки выбора файлов и папки вызывают системный `tkinter`-диалог на локальной машине;
- список отображается карточками с состоянием и progress bar;
- настройки сохраняются в `localStorage`;
- тяжёлая обработка выполняется в фоновом worker;
- одновременно разрешена одна активная задача, чтобы не дублировать модель в VRAM;
- события `job`, `file`, `log`, `done` передаются через SSE с монотонным event id;
- `/api/active-job` восстанавливает состояние после перезагрузки страницы и рестарта процесса;
- persisted snapshot содержит настройки, source fingerprint, стадии, результаты и ошибки;
- незавершённая при рестарте задача терминализируется как `interrupted` и доступна для retry;
- cancel кооперативно останавливает очередь и текущий backend в безопасной точке;
- retry создаёт новую задачу только для `error`/`cancelled` элементов;
- picker/refresh-запросы сериализуются, а устаревший ответ игнорируется.

Экран V1.4:

- слева — выбранные файлы, сводка статусов и действия `Выбрать файлы`, `Выбрать папку`,
  `Обновить`, `Распознать`, а для задачи — `Отменить` и `Повторить ошибки`;
- справа — backend, локальная ASR-модель, optional aligner, язык речи, устройство, выбор
  аудиопотока и параметры сохранения;
- снизу — журнал обработки;
- карточка файла показывает `queued`, `probing`, `extracting`, `transcribing`, `writing`,
  `aligning`, `cached`, `skipped`, `done`, `cancelled` или `error`, текущую стадию и пути результатов.

В первой версии нет браузерной загрузки больших MP4 в память. UI работает с локальными
путями, выбранными backend-диалогом, и поэтому предназначен только для localhost.

## API веб-интерфейса

- `GET /api/health` — состояние приложения, FFmpeg и модели без загрузки весов.
- `GET /api/ui-config` — значения по умолчанию и доступные варианты без секретов.
- `GET /api/active-job` — snapshot текущей или последней задачи и последние строки журнала.
- `GET /api/jobs` и `GET /api/jobs/{job_id}` — persisted история и конкретный snapshot.
- `POST /api/pick` — открыть локальный диалог выбора файла/папки.
- `POST /api/refresh` — повторно выполнить probe и собрать карточки выбранных путей.
- `POST /api/transcribe` — запустить одну фоновую задачу; при занятом worker вернуть `409`.
- `POST /api/jobs/{job_id}/cancel` — запросить кооперативную отмену активной задачи.
- `POST /api/jobs/{job_id}/retry` — повторить только неуспешные элементы terminal-задачи.
- `GET /api/stream/{job_id}` — SSE-поток с keep-alive и cursor/`Last-Event-ID`.
- `POST /api/unload` — выгрузить локальную модель и освободить GPU/CPU память.

Минимальный контракт событий:

```json
{"type":"file","path":"...","state":"transcribing","stage":"ASR","progress":42}
```

```json
{"type":"done","status":"ok|partial|error|cancelled|interrupted","done":2,"cached":1,"failed":1}
```

Snapshot, файловые состояния и ограниченная история событий хранятся в SQLite по пути
`WEB_JOB_DB`. Terminal-задачи доступны после рестарта. Незавершённая работа не выдаётся за
успешную: при открытии БД она получает terminal-статус `interrupted`, после чего пользователь
может явно запустить retry. SSE reconnect продолжает поток после последнего принятого event id.

Пути с пробелами, кириллицей и другими Unicode-символами обязательны для тестирования.

## Выбор и подготовка аудиопотока

1. `ffprobe` запускается до FFmpeg и возвращает JSON.
2. Явный `audio_stream_index` имеет наивысший приоритет.
3. Иначе выбирается единственный поток с совпадающим `language` или `title`.
4. Если аудиопоток один, используется он.
5. Если выбор неоднозначен, используется первый аудиопоток только с видимым предупреждением;
   пользователь может задать индекс и обновить список до запуска.
6. FFmpeg вызывается списком аргументов без `shell=True`.
7. Обязательные параметры: `-nostdin`, явный `-map`, `-vn`, `-ac 1`, `-ar 16000`,
   `-c:a flac` и проверка кода завершения.
8. Временный результат создаётся внутри `resources/work/<job_id>` и не считается готовым,
   пока FFmpeg не завершился успешно и длительность не проверена.
9. Флаг `keep_audio` копирует нормализованный FLAC в целевой каталог. Архивное извлечение
   исходного bitstream через `-c:a copy` оставлено за пределами первой версии.

## Локальные ASR-модели

Основной long-form backend: `faster-whisper`/CTranslate2.

Основной checkpoint:

```text
D:\Projects\-ai\+automatic-speech-recognition\whisper-large-v3-ct2
```

Fallback Transformers checkpoint:

```text
D:\Projects\-ai\+automatic-speech-recognition\whisper-large-v3
```

Дополнительные checkpoint-ы V1.4:

```text
D:\Projects\-ai\+automatic-speech-recognition\parakeet-tdt-0.6b-v3
D:\Projects\-ai\+automatic-speech-recognition\Qwen3-ASR-0.6B
D:\Projects\-ai\+automatic-speech-recognition\Qwen3-ForcedAligner-0.6B
```

Требования:

- модель и processor загружаются только из локального пути;
- обычный запуск не выполняет сетевое скачивание;
- при CUDA используется FP16 либо поддерживаемая 8-битная конфигурация;
- `--no-quantization` отключает только квантование;
- CPU fallback выполняется только при явно заданном разрешении;
- модель загружается один раз и повторно используется для файлов задачи;
- ASR backend возвращает единый типизированный контракт transcript/segments/words/metadata;
- optional aligner принимает нормализованное аудио, общий transcript, длительность и
  progress/cancel callbacks, затем возвращает тот же контракт с уточнёнными words;
- registry лениво создаёт backend и держит только одну тяжёлую модель активной;
- faster-whisper декодирует запись окнами через PyAV и не материализует весь PCM;
- long-form параметры входят в cache fingerprint только выбранного backend;
- fingerprint отдельно фиксирует backend, ASR-модель, runtime, aligner, его модель и параметры;
- модель не пишет SRT напрямую: форматирование выполняет общий SRT builder;
- после `/api/unload` ссылки на model/processor освобождаются, выполняется очистка CUDA cache.

Реализованные профили V1.4:

- Parakeet TDT v3 работает в изолированном Python 3.14 worker с Transformers 5.14.1;
- Qwen3-ASR и ForcedAligner работают последовательно в отдельных worker-процессах одного
  изолированного Python 3.11 runtime с `qwen-asr 0.0.6` и Transformers 4.57.6;
- worker-ы обмениваются framed NDJSON, загружают только локальные checkpoint-ы и используют
  CUDA либо явно разрешённый CPU fallback;
- Parakeet нормализует нативные token timestamps в words/segments и обрабатывает long-form
  окнами;
- Qwen3-ASR формирует неперекрывающиеся coarse-сегменты с target 175 секунд и верхней границей
  180 секунд; самостоятельный Qwen ForcedAligner режет аудио по этим сегментам, применяет
  offsets и возвращает монотонные словные временные метки;
- alignment adapter не зависит от Qwen ASR: он принимает transcript любого backend-а при
  определённом языке `en`/`ru`, делит длинные сегменты по словным меткам и паузам либо
  пропорционально тексту и времени и передаёт worker-у части до 180 секунд.

Точные зависимости изолированных runtime-ов находятся в `requirements-workers/parakeet.txt`
и `requirements-workers/qwen.txt`; воспроизводимая установка выполняется `setup_workers.ps1`.
WhisperX прошёл compatibility spike, но не включён: нет воспроизводимого локального RU aligner,
pyannote pipeline и NLTK assets, а основной Python 3.14 не поддерживается. Общий alignment
registry сохранён как extension point.

Облачные API не входят в работающий макет. Их возможное добавление не должно менять
контракты batch service, SRT builder и UI состояний.

## Формирование SRT

Распознавание текста и построение тайминга считаются отдельными задачами.

SRT builder:

1. Предпочитает словные временные метки; при их отсутствии использует сегментные.
2. Создаёт границы по пунктуации, паузам и лимитам читаемости.
3. Формирует не более двух строк на cue.
4. Использует настраиваемый ориентир 42 символа в строке.
5. Ограничивает длительность cue диапазоном примерно 0.8–7 секунд, не обрезая речь.
6. Не допускает отрицательных меток и пересечений.
7. Форматирует время как `HH:MM:SS,mmm`.
8. Сохраняет последовательную нумерацию с единицы.
9. Пишет только UTF-8 без BOM.

Валидатор проверяет непустой текст, синтаксис, `end > start`, монотонность, отсутствие
пересечений и то, что последняя реплика не выходит за длительность аудио сверх допуска.

## Выходные данные

Для `lecture.mp4` по умолчанию создаются:

```text
lecture.en.srt
lecture.en.asr.json
```

Sidecar JSON содержит:

- абсолютный путь, размер, `mtime` и SHA-256 источника;
- длительность и выбранный аудиопоток;
- backend, путь/идентификатор модели, устройство и значимые параметры;
- optional aligner, его checkpoint/runtime и параметры выравнивания;
- язык, нормализованные segments/words и версию SRT builder;
- путь SRT, время начала/окончания и итоговый статус.

Если задан `--output-dir`, относительная структура входной папки сохраняется, чтобы файлы
с одинаковыми именами не конфликтовали.

SRT, sidecar и сохраняемый FLAC подготавливаются во временных соседних файлах. Межпроцессный
lock исключает двух одновременных писателей одного результата; commit восстанавливает
предыдущий согласованный набор при частичном сбое. При ошибке не остаётся пустой `.srt`,
выдаваемый за готовый результат.

## Кеш и идемпотентность

Ключ готового результата включает:

- fingerprint источника;
- выбранный аудиопоток;
- backend и модель;
- aligner, его модель/runtime и параметры;
- язык и устройство/precision, если они влияют на результат;
- параметры распознавания и SRT builder;
- версию пайплайна.

Правила:

1. Валидный SRT + совпадающий sidecar дают статус `cached` без загрузки модели.
2. Существующий SRT без подтверждающего sidecar не перезаписывается и получает `skipped`.
3. Повреждённый SRT не считается кешем.
4. `force` игнорирует кеш, но заменяет только вычисленные целевые файлы.
5. Изменение источника или значимых настроек инвалидирует кеш.
6. Кеш не основывается только на basename, чтобы исключить коллизии между папками.
7. Fingerprint содержит фактические device и quantization результата; `auto`/CPU fallback не
   переиспользуют результат другого runtime как совпавший кеш.

## Переменные окружения

- `ASR_BACKEND`, `ASR_MODEL_PATH` — backend и его локальный checkpoint.
- `ASR_ALIGNER`, `ASR_ALIGNER_MODEL_PATH` — optional aligner и его локальный checkpoint.
- `ASR_WORKER_PYTHON` — явный Python worker-а выбранного backend-а.
- `ASR_ALIGNER_WORKER_PYTHON` — независимый Python worker-а выбранного aligner-а.
- `QWEN_ASR_PYTHON`, `PARAKEET_ASR_PYTHON` — backend-специфичные worker runtime-ы.
- `ASR_LANGUAGE` — язык по умолчанию, `en`.
- `ASR_AUDIO_LANGUAGE`, `ASR_AUDIO_STREAM_INDEX` — предпочитаемый язык и явный поток.
- `ASR_DEVICE` — `auto|cuda|cpu`.
- `ASR_QUANTIZATION` — включение поддерживаемой 8-битной загрузки.
- `ASR_ALLOW_CPU_FALLBACK` — явное разрешение fallback.
- `ASR_KEEP_AUDIO`, `ASR_OUTPUT_DIR` — сохранение FLAC и каталог результата.
- `FFMPEG_PATH` — путь к `ffmpeg`, если его нет в `PATH`.
- `FFPROBE_PATH` — путь к `ffprobe`, если его нет в `PATH`.
- `HF_HOME`, `HUGGINGFACE_HUB_CACHE` — локальные кеши Hugging Face.
- `WEB_HOST`, `WEB_PORT` — адрес и порт локального интерфейса.
- `WEB_JOB_DB` — путь persistent SQLite-хранилища web-задач.
- `RUN_LOCAL_ASR_TEST` — явное включение тяжёлой интеграционной проверки.
- `ASR_TEST_MEDIA`, `ASR_TEST_LANGUAGE` — медиафайл и язык этой проверки.

Значения по умолчанию и назначение каждой переменной документируются в README. Секреты для
первой версии не требуются.

## Нефункциональные требования

- Windows и PowerShell — основное окружение; пути с Unicode и пробелами обязательны.
- Веб-сервис принимает только loopback bind; внешний адрес без защищённого remote-режима
  отклоняется до запуска.
- После установки зависимостей и размещения модели рабочий сценарий полностью локальный.
- Исходные файлы не изменяются и не удаляются.
- FFmpeg запускается без shell-интерпретации пользовательских путей.
- Большие медиа не читаются целиком в память веб-приложения.
- Для одной GPU одновременно работает один ASR worker.
- Ошибка одного файла не прерывает пачку.
- Все пользовательские сообщения, комментарии, docstring и логи — на русском языке.
- Выходные текстовые файлы — UTF-8 без BOM.
- Тяжёлая модель не загружается при cache hit или ошибке preflight.
- Сгенерированные `*.asr.flac` не становятся новым входом при повторном обходе папки.
- Реестр задач и журналы имеют ограниченный размер; завершённые задачи очищаются по TTL.
- Очистка рабочего каталога затрагивает только устаревшие `job-*` с валидным lock-маркером,
  находящиеся непосредственно внутри `resources/work`; symlink и активная блокировка исключают удаление.
- Фактические скорость и VRAM измеряются на целевой машине и не обещаются по чужим benchmark.

## Тестирование

Unit-тесты без загрузки модели:

- валидация расширений и путей;
- разбор `ffprobe` JSON и политика выбора аудиопотока;
- безопасная сборка аргументов FFmpeg;
- форматирование временных меток и SRT;
- запрет пересечений и пустого результата;
- UTF-8 без BOM и атомарная запись;
- fingerprint кеша и его инвалидация;
- выбор GPU/CPU и квантования через моки;
- batch service с fake ASR backend;
- ошибка одного файла не останавливает остальные;
- API health/config без секретов;
- одна активная задача и `409` для второй;
- порядок SSE-событий, partial status и terminal snapshot;

- cancel ожидающих/текущего файла и retry только неуспешных элементов;
- сохранение source fingerprint в persisted файловом snapshot;
- отдельные fingerprint backend-а, модели, aligner-а и runtime;
- адаптеры Parakeet/Qwen и протокол изолированного worker-а через моки;
- фильтрация файлов локального picker.

## Критерии приёмки работающего макета

Первая версия считается готовой, когда:

- `AGENTS.md` и `requirements.txt` перенесены из свежего каркаса `ocr-local` и адаптированы
  только там, где этого требует новый домен;
- веб-пакетная механика из `sub-translator-py` перенесена и адаптирована под media -> ASR -> SRT;
- `python -m speech_to_sub.web` и `run_web.ps1` запускают localhost UI;
- preflight подтверждает наличие FFmpeg, ffprobe и локального checkpoint без загрузки весов;
- CLI и web используют один service layer;
- пачка минимум из трёх файлов отображает отдельные статусы и завершается, даже если один
  файл повреждён;
- MP4 с несколькими аудиопотоками обрабатывает явно выбранную дорожку;
- для успешного файла создаются непустые валидные `.srt` и `.asr.json` в UTF-8 без BOM;
- повторный запуск использует валидный кеш без загрузки модели;
- существующий неподтверждённый SRT не перезаписывается без `force`;
- тесты проходят командой `python -m pytest`;
- opt-in интеграционные проверки способны выполнить локальное распознавание через Whisper,
  Parakeet TDT v3 и Qwen3-ASR + ForcedAligner на доступном устройстве;
- web-задача и файловые состояния сохраняются в SQLite, recovery не выдаёт прерванную работу
  за успешную, а cancel/retry не переобрабатывают уже готовые результаты;
- cache fingerprint раздельно учитывает ASR backend/model/runtime и optional aligner.

## Статус работающего макета

На 8 августа 2026 года функциональные блоки V1–V1.4 реализованы. CLI и FastAPI UI используют
общий batch service, ASR/alignment registry, ffprobe/FFmpeg подготовку, SRT builder/validator и
runtime-aware sidecar-кеш. V1.1 подтверждена реальным multi-track MP4, live batch с повреждённым
файлом, повторным cache pass и Playwright E2E после reload.

V1.3 хранит задачи, настройки, source fingerprint, файловые состояния, ошибки и события в
SQLite. После рестарта незавершённая задача становится `interrupted`; cancel работает на
очереди и безопасных точках backend-а, retry запускает только неуспешные элементы. SSE cursor
не воспроизводит принятые события. Picker/refresh защищены от устаревших ответов, а TTL cleanup
удаляет только управляемые неактивные workspace, не пользовательские исходники.

V1.2 подтверждена benchmark-ом четырёх предоставленных RU/EN MP4/MKV. faster-whisper
обработал часовой русский MKV с RTF `0,188`, постоянным диапазоном памяти и без граничных
дублей. На одинаковом EN MP4 он оказался в 8,1 раза быстрее Transformers и существенно легче
по RAM/VRAM, поэтому выбран default для long-form. Методика и JSON-артефакты находятся в
[docs/benchmarks/v1.2](docs/benchmarks/v1.2/README.md).

Остающийся quality-риск — отсутствие эталонных расшифровок для WER/CER и абсолютной
timestamp MAE. Transformers по-прежнему материализует полный float32 PCM и остаётся только
fallback для совместимости, а не рекомендуемым runtime длинных записей.

V1.4 добавила Parakeet TDT v3, Qwen3-ASR 0.6B и самостоятельный ForcedAligner 0.6B через
изолированные локальные worker-ы. После устранения дублей на границах окон Parakeet прошёл
CUDA long-form на RU 375,520 с (`RTF 0,073654`) и EN 338,152 с (`RTF 0,077936`).
Последовательные Qwen ASR → unload → ForcedAligner прошли RU/EN smoke и EN 338,152 с
(`RTF 0,383180`): два ASR-сегмента до 180 секунд дали 832 монотонные словные метки, включая
44 после 300-й секунды. В едином short benchmark сохранены восемь RU/EN JSON для четырёх
backend-ов; RSS измеряется по дереву процессов, так что память изолированного worker-а
учитывается. Методика и результаты находятся в
[docs/benchmarks/v1.4](docs/benchmarks/v1.4/README.md).

WhisperX проверен отдельно и осознанно отложен из-за отсутствия полного локального RU/EN
набора alignment/diarization assets и несовместимости с основным Python 3.14. Архитектурная
точка расширения сохранена. Финальные общий прогон тестов и независимый аудит отмечаются
только после отдельного подтверждения в [CHECKLIST.md](CHECKLIST.md).
